# Institution logo (Portal Appearance)

One logo per institution. Administrators upload it in **Admin → Portal Appearance → Institution logo**,
next to the colour theme and typography; it applies at once for everyone at the institution, including
the signed-out sign-in page. A chosen file is previewed first and applied with **Apply logo**; **Restore
default** goes back to the logo bundled with the deployment.

## Where it appears
The same uploaded logo replaces the bundled one in every branding location, contained in each spot's
existing height (never stretched or cropped):
navigation sidebar (top left) and its collapsed rail, sign-in page and its opening animation, mobile
header, loading screen, printed transcripts, and the "install the portal" prompt. On the dark navy
surfaces (sidebar, sign-in page, crest spots) it sits on a small light plate, so a logo of any colour
stays legible; there are no light/dark variants to upload.

## Files
- PNG, JPEG or WebP, up to 1 MB, at least 48 px high, between a square crest (1 : 1) and a 6 : 1
  lockup. Recommended: transparent PNG about 200 px high (e.g. 700 × 200 px). SVG is not accepted (an
  uploaded SVG can carry script). The server checks the real file content and size.

## Storage (deployment)
- The image file is stored by the backend in **`BRANDING_STORAGE_DIR`** (default
  `backend/storage/branding`, git-ignored), as `<tenant id>/<sha-256>.<png|jpg|webp>`. Names are always
  generated by the server. Set `BRANDING_STORAGE_DIR` to a persistent directory **outside the code
  checkout** (e.g. `/var/lib/edunexus/branding`, writable by the backend user) so redeployments keep it,
  and include it in server backups. With more than one backend instance, every instance must see the
  same directory (shared volume).
- The database keeps only the reference and metadata: `tenant_brand_assets` (kind `logo`: storage key,
  type, size, dimensions, sha-256). Migrations `20261029100000_tenant_brand_assets` and
  `20261029120000_brand_logo_file_storage` (additive; the first version's inline-bytes column is kept,
  nullable and unused).
- API: `GET /api/v1/appearance` returns `logo` (or null). `GET /api/v1/appearance/logo/:tenant?v=<version>`
  serves the file publicly (cached for good per version; a new upload is a new address, so no one needs
  to clear their cache; `nosniff`, sandboxed). `PUT` / `DELETE /api/v1/appearance/logo` — administrators of
  their own institution only; audited (`APPEARANCE_LOGO_UPDATED`, `APPEARANCE_LOGO_RESET`).
- If the file is missing, the logo address answers 404 and the portal shows the bundled logo.

## Deployment default (no upload)
The portal shows the files bundled in `frontend/public` (`feddrick-university-logo-inverse.svg` on dark
surfaces, `feddrick-university-logo.svg` on light ones, `feddrick-university-mark.svg` as the crest),
referenced from `frontend/src/branding.js`. A deployment can replace those files instead of uploading.
The browser-tab icon and installed-app icons (`frontend/public/icons`, `manifest.webmanifest`) are
deployment files and are not changed by an upload.
